# 失敗の記録

このリポジトリで作業するエージェントの失敗と、その対策。見出しから同じ失敗を探し、なければ新しいものを上に書く。
同じ失敗が2回起きたら防止策を入れ、入れたら「対策済み」にして残す。

### 複数の意味に取れる依頼を、確認せずに一方の意味で進める

- **状態**: 観察中
- **起きたこと**: ui.md の見直しで、オーナーが「書き直して」と言った。このとき、どうするかをオーナーに任せていた2つの原則（データの上に重ねるとき、前回の選択を初期値にする）も、確認せずに消した。報告では「戻せる」と伝えたが、先に確認すべきだった
- **回数**: 1（2026-11-07）
- **ツール・モデル**: Claude Code / Opus 5.5
- **原因**: 指示がなかった（このリポジトリの AGENTS.md に、曖昧な依頼を確認する手順がない）
- **対策**: 生成先のテンプレートの AGENTS.md には、「着手前」に確認の手順を入れた。このリポジトリでは、評価役の確認項目に入れた（作業手順には、2回目が起きるまで入れない）
- **見直す条件**: このリポジトリで2回目が起きたら、ルートの AGENTS.md の作業手順に入れる

### 変更を継ぎ足すだけで、変更後の全体として書き直さない

- **状態**: 対策済み（skill のテンプレート・ガイドライン・原則と、このリポジトリの AGENTS.md）
- **起きたこと**: 修正を何回も重ねるうちに、注記・例外・新しい節を末尾に足していき、ファイルの構成が足した順になった。framework.md、principles.md、SKILL.md、agent-tools.md、テンプレートの AGENTS.md・CLAUDE.md・failures.md、ルートの AGENTS.md で起きた。オーナーはコードとコメントでも同じ傾向を観察している
- **回数**: 複数回（2026-11-07 のやり取り全体）
- **ツール・モデル**: Claude Code / Opus 5.5
- **原因**: 指示がなかった。加えて、「必要な範囲だけ変更する」というルールが、関係するまとまりの書き直しまで避ける方向に働いていた。確認も差分しか見ていなかった
- **対策**: 原則10「継ぎ足さず、変更後の全体として書き直す」を追加。テンプレートの AGENTS.md で、変更の範囲を「目的に関係するまとまりは全体として書き直す、関係しないものには触らない」に定義し直し、完了の条件を「変更したまとまりを頭から読み直す」にした。ガイドライン（coding / design / documentation）に書き直し方を追加。評価役のサブエージェント（生成先のテンプレートと、このリポジトリの `.claude/agents/evaluator.md`）を標準にし、確認項目に入れた
- **見直す条件**: 評価役を入れても同じ傾向が続くなら、差分のコメントに経緯の言葉（「変更」「以前は」「v2」など）があれば警告する検査を足す

### Edit / Write を使わず、Python などでファイルを書き換える

- **状態**: 対策済み（skill のテンプレートと、このリポジトリの CLAUDE.md）
- **起きたこと**: ファイル編集のツールを使わずにスクリプトで書き換えることがある（オーナーが複数回観察）。hook や権限の設定が働かず、変更箇所も見えにくくなる
- **回数**: 複数回（日付の記録なし）
- **ツール・モデル**: Claude Code / Opus 5.5（モデル特有かは不明）
- **原因**: 指示がなかった
- **対策**: `CLAUDE.md` のテンプレート（`claude-instructions.md`）と、このリポジトリの `CLAUDE.md` に指示を追加。formatter などは pre-commit と CI にも置くよう `references/agent-tools.md` に記載
- **見直す条件**: モデルを更新したとき
