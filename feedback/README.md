# 試行の記録

harness-creator を実際のプロジェクトで使った結果を、skill に戻すための記録。1回試すごとに1ファイル（`YYYY-MM-DD-<プロジェクト名>.md`）を作る。
記録は git に入れず、手元にだけ置く（`.gitignore` で、このファイル以外を除いている。理由は `docs/decisions.md` の D-015）。skill を直した理由は、記録を見なくても分かるように `docs/decisions.md` に書く。
生成先のプロジェクトでの改善は、そのプロジェクトの `docs/failures.md` で行う。ここには、skill のテンプレートや手順が原因のものだけを書く。

## 振り返りの材料

- **テンプレートと生成物の差分**: 消された行・大きく書き換えられた行。どのプロジェクトでも消される行は不要、毎回書き換えられる行は書き方が分かりにくい
- **生成したときの会話の記録**（Claude Code は `~/.claude/projects/` に保存している）: どこで迷ったか、オーナーが何を訂正したか
- **skill の最後の報告**: 合わなかった箇所、迷った点、未確認の項目
- **生成先の `docs/failures.md`**: 使い始めてから起きた失敗のうち、テンプレートが原因のもの

## 改善に回す基準

- 同じ問題が2回の試行で出たら、テンプレートや手順を直し、理由を `docs/decisions.md` に書く。直したら、該当する記録に直したことを書く
- 1回だけなら記録に留める。1つのプロジェクトの事情に合わせすぎないため。どのプロジェクトでも起きると分かる問題は、オーナーの判断で1回目から直すことがあり、そのときは理由を `docs/decisions.md` に書く

## 記録の形

```markdown
# YYYY-MM-DD <プロジェクト名>

- **プロジェクト**: 何を作っているか、言語・技術、新規か既存か
- **レベル・ツール・モデル**: L1、Claude Code / Opus 5.5 など
- **ヒアリング**: 答えにくかった質問、聞かれなかったが必要だった質問
- **生成物を直したところ**: どのファイルのどこを、なぜ
- **迷った点・合わなかった箇所**: skill の報告と会話の記録から
- **使い始めてからの失敗**: テンプレートが原因のもの
- **改善案**: skill のどこを、どう直すか
```
