# evals: ハーネスの効き目を測る

同じタスクを、条件（ハーネスのあるなし・モデル）を変えて Claude Code に人の操作なしで実行させて比べる。判断の経緯は [docs/decisions.md](../docs/decisions.md) の D-029。

このハーネスで良くしたいのは、頼んだことができるかより、設計の良さとコードや文書の読みやすさなので、次の順で見る。

1. **仕様変更を重ねたときの手間と崩れ方**: 1回目の依頼のあと、同じフォルダで仕様変更を何回か続けて頼み、依頼ごとの変更の大きさ、コードの太り方、古い記述や経緯の言葉が残るかを見る
2. **ばらつき**: 同じ条件を3回以上実行し、全回で成功したか（安定して成功するか）と、指標の幅を見る。数回の差で結論を出さない
3. **ハーネスの重さ**: 簡単なタスク（`small-fix`）で、ハーネスがあるとコストと時間がどれだけ増えるかを見る
4. **モデルとの組み合わせ**: 「L1＋Haiku」が「ハーネスなし＋Sonnet」にどこまで近づくかを見る

隠しテストの合否は、前提条件として見る。主観的な品質（オーナーの開発ガイドラインに合っているか）の採点は、まだない。

## 実行のしかた

```bash
evals/run.sh reduced-tax none          # ハーネスなしで1回
evals/run.sh reduced-tax l1            # L1 のハーネスありで1回
evals/run.sh reduced-tax l1 haiku      # モデルを変える（既定は sonnet）
evals/summarize.sh reduced-tax         # 結果を依頼・条件ごとの表にする
```

1回ごとに、使ったトークンの分だけ Claude の利用枠が減る（定額プランでも）。1回の依頼の上限は、API の料金に換算して $3 にしている（`run.sh` の `budget_usd`）。何回も実行する前に、1回でどれだけ使うかを `/usage` で確かめる。

## 1回の実行でしていること

1. タスクの `repo/` を、このリポジトリの外の一時フォルダに写す。`l1` なら `harness-l1/` を重ね、最初のコミットを作る。このリポジトリの中で実行すると、ここの `CLAUDE.md` が読み込まれるため
2. `prompt.md` の依頼で `claude -p` を実行する。`--setting-sources project,local` と `--strict-mcp-config` で、実行する人のユーザー設定・プラグイン・MCP を読まない。確認で止まらないよう、権限は両方の条件とも `auto` にする。エージェントが何も変えずに終わり、返答に問いや承認・確認を求める言葉があれば（「これで進めてよいですか？」「承認をもらえたら進めます」など）、人の代わりに「はい、その内容で進めてください。」と同じセッションに返して続けさせる（最大2回）。返さないと、人がいれば続く場面で何もせずに終わるため。返した回数は、ユーザーの手間として `confirmation_replies` に残す。確認を求める前に記録（progress.md など）を書き換えた回は、変更があるので返事をせず、そこで終わる。続けるためにセッションを保存するので、`~/.claude/projects/` に一時フォルダの分の記録が残る
3. `check.sh` で、元からあるテスト（`repo/` にある、エージェントが書き換える前の版）と、エージェントに見せない隠しテスト（`hidden_tests/`）を実行する。落ちた隠しテストの名前も残す
4. `metrics.py` で、コードと文書を数える（数えるものは `metrics.py` の先頭に書いてある）。関数の長さと分岐の数、2つ以上のファイルに書かれた数、使われない関数、テストの数、変えた行数、決まりの文書を直したか、古い記述、経緯の言葉
5. タスクに `followups/` があれば、ここまでの結果をコミットし、同じフォルダでその中の依頼を名前の順に1つずつ、新しいセッションとして実行し、隠しテストと 4 で確かめる（元からあるテストは、仕様が変わって期待値が古くなるので実行しない）。会話は引き継がないので、ハーネスの記録（progress.md など）が続きに役立つかも見える。古い記述は、それまでの依頼の `stale.txt` を全部使って調べる
6. `results/<タスク>/<日時>-<条件>-<モデル>/` に、結果（`result.json`。依頼ごとの結果は `steps` に順に入る）、依頼ごとの会話の全体（`<依頼>.stream.jsonl`）と変更の差分（`<依頼>.diff.patch`）を残し、一時フォルダを消す

`results/` は git に入れない。各依頼の結果の `loaded` に、実行時に読み込まれたプラグイン・MCP・サブエージェント・skill が入る。ユーザーの設定が混ざっていないかは、ここで確かめる。

`summarize.sh` は、依頼ごとの結果、依頼のあとのコード、1回の実行の合計の3つの表を出す。回数が2回以上の条件は、平均の後ろに「(最小〜最大)」を付ける。

## タスク

| タスク | 中身 |
|---|---|
| `reduced-tax` | 軽減税率に対応する。依頼文では何も示さず、決まりは `docs/pricing.md` にだけある。返金の計算が税率を別に持っている。そのあと、標準税率を12%に、端数を四捨五入に、非課税の商品を足す、の3回の仕様変更を続ける |
| `small-fix` | `Cart.item_count()` を足すだけの簡単なタスク。`repo/`・`harness-l1/` は `reduced-tax` のものへのリンク |
| `coupon` | クーポンに対応する。依頼文で決まりのファイルを示しているので、ハーネスなしでも通る。最初に作ったタスクとして残している |

### タスクの作り方

`tasks/<タスク名>/` に次を置く。

| ファイル | 中身 |
|---|---|
| `repo/` | サンプルのプロジェクトの初めの状態。元からあるテストが通る |
| `prompt.md` | エージェントに渡す依頼文。普段の依頼と同じくらいの短さにする |
| `hidden_tests/` | 合否を決めるテスト。作るときに、正しい実装で全部通ることを確かめる |
| `followups/<番号>-<名前>/` | なくてよい。1回目のあとに続けて頼む仕様変更。名前の順に実行するので、番号を頭に付ける。中に依頼文（`prompt.md`）と、その時点の仕様全体を確かめる隠しテスト（`hidden_tests/`）を置く。前の依頼で決めたことも確かめ、壊していないかを見る。その依頼で古くなる記述があれば、それに当たる Python の正規表現を `stale.txt` に1行に1つ書く |
| `check.sh` | なくてよい。Python の unittest のタスクは `evals/check.sh` で確かめる。別の言語のタスクでは、タスクのフォルダとその作業フォルダを受け取り、`existing_tests_pass`・`hidden_pass` などを1行の JSON で出すものを置く |
| `harness-hearing.md` | ハーネスを生成するときに渡すヒアリングの答え |
| `harness-l1/` | `repo/` に harness-creator で生成した L1 のハーネス。`evals/make-harness.sh <タスク名>` で作り、固定する |

差が出るのは、エージェントが間違えやすいタスクだけ。依頼文には書かず、プロジェクトの中の文書にだけある決まり（端数の扱い、表示の形など）や、変えた処理を別に持っている場所（同じ計算を写した別のモジュールなど）を含める。仕様変更は、1回目の作りが悪いと手間が増えるもの（定数を1か所にまとめたか、丸めを1か所でしているか、種類が2つである前提で書いていないか）にする。

### ハーネスの置き方

`make-harness.sh` は、一時フォルダで `claude -p` に skill の手順で生成させ、変わったファイルだけを `harness-l1/` に写す。git に入れないもの（`docs/local/`）は写さず、clone した直後と同じ状態にする。`CLAUDE.md` は `claude-instructions.md`、`.claude/` は `_claude/` という名前で置き、`run.sh` が写すときに戻す。元の名前のままだと、このリポジトリで作業する Claude Code が、そのフォルダを読んだときに指示や設定として読み込むため。

skill を変えたら、`harness-l1/` を作り直す。生成したモデルは `harness-l1/docs/decisions.md` に残る。生成したときの skill のコミットは `make-harness.sh` が最後に出すので、`harness-l1/` を足すコミットのメッセージに書く。`small-fix` のようにリンクで共有しているタスクは、リンク先のタスクで作り直す。
