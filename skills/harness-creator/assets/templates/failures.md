# 失敗の記録

エージェントの失敗と、入れた対策の記録。ハーネスを育てるために使う。

## 使い方

- 失敗に気づいたら、「記録」の見出しから同じ失敗を探し、あれば回数を更新する。なければ新しいものを上にして書く。見出しは、何が起きたかが分かる一文にする（全部を読まずに探せるようにするため）
- 同じ失敗が2回起きたら、防止策を入れる。置き場所は「防止策の置き場所」の表で選ぶ
- 対策を入れたら「対策済み」にして残す。その仕組みが何のためにあるかの記録になるため。仕組みを外したときは、外した理由を書き足す
- 指示はモデル名ではなく行動で書く。モデルを更新したら、各項目の「見直す条件」を確かめる

## 防止策の置き場所

上ほど確実。機械的に検査できるものは、文章に書くだけで済ませない。

| 置き場所 | 向いているもの |
|---|---|
| CI・lint・テスト | コードの規約違反、構造の崩れ |
| pre-commit | コミット前に揃っていればよいもの（整形、秘密情報の検出）。人にもどのツールにも効く |
| エージェントの hook | 実行前に止めたいもの、編集直後に結果を返したいもの |
| エージェントの権限設定 | 読ませたくないファイル、使わせたくないツール |
| skill・コマンド | 手順が長く、順番を間違えやすい作業 |
| サブエージェント | 自己評価が甘くなる作業（レビュー、継ぎ足しになっていないかの確認） |
| `AGENTS.md`・`docs/` | 判断が必要で、機械的に検査できないこと |

## 記録

### （記入例）テストを実行せずに「完了」と報告した

- **状態**: 対策済み / 観察中
- **起きたこと**: 何が起き、どんな影響があったか
- **回数**: 2（YYYY-MM-DD, YYYY-MM-DD）
- **ツール・モデル**: Claude Code / Opus 5.5 など
- **原因**: 指示がなかった / 指示はあったが守られなかった / 手段がなかった
- **対策**: どこに何を入れたか（例: Stop hook でテストを実行）
- **見直す条件**: モデルを更新したとき など
