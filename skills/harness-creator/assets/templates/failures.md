# 失敗の記録

エージェントが同じ失敗を繰り返さないための記録。1件は数行にする。

## 使い方

- 失敗に気づいたら、「記録」の見出しから同じ失敗を探し、あれば回数を足す。なければ新しいものを上にして書く。見出しは、何が起きたかが分かる一文にする（全部を読まずに探せるようにするため）
- 同じ失敗が2回起きたら防止策を入れ、何をどこに入れたかを「対策」に書く。詳しい理由は、その対策を入れたコミットのメッセージに書く
- 対策済みの項目も消さない。その仕組みが何のためにあるかの記録になるため。仕組みを外したら、外したことを書き足す
- ここには、このリポジトリで作業する誰に起きてもおかしくない失敗だけを書く。一人の環境（OS、ツールの設定、手元のデータ）でだけ起きる失敗は書かず、防止策をその人の設定（Claude Code の `.claude/settings.local.json` など、git に入れないもの）に入れる
- 指示はモデル名ではなく行動で書く。モデルを新しくしたら、対策がまだ要るかを見直す

## 防止策の置き場所

上ほど確実。機械的に検査できるものは、文章に書くだけで済ませない。

| 置き場所 | 向いているもの |
|---|---|
| CI・lint・テスト | コードの規約違反、構造の崩れ |
| pre-commit | コミット前に揃っていればよいもの（整形、秘密情報の検出）。人にもどのツールにも効く |
| エージェントの hook | 実行前に止めたいもの、編集直後に結果を返したいもの |
| エージェントの権限設定 | 読ませたくないファイル、使わせたくないツール |
| skill・コマンド | 手順が長く、順番を間違えやすい作業 |
| サブエージェント | 自己評価が甘くなる作業（レビュー、継ぎ足しになっていないかの確認） |
| `AGENTS.md`・`docs/` | 判断が必要で、機械的に検査できないこと |

## 記録

### （記入例）テストを実行せずに「完了」と報告した

- **回数**: 2（Claude Code / Opus 5.5 など、起きたツールとモデル）
- **対策**: Stop hook でテストを実行する（対策済み）。まだなら「観察中」
